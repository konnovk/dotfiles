# Neovim Config

## Установка

Создайте резервную копию текущей конфигурации, если она существует:

```bash
mv ~/.config/nvim ~/.config/nvim.backup-$(date +%Y%m%d-%H%M%S)
```

Клонируйте репозиторий в каталог конфигурации Neovim:

```bash
git clone git@github.com:konnovk/nvim-config.git ~/.config/nvim
```

Запустите Neovim:

```bash
nvim
```

При первом запуске `vim.pack` автоматически загрузит плагины.

Конфигурация Neovim на Lua с использованием только встроенных механизмов управления плагинами и LSP.

- **Neovim:** `0.12.x`
- **Плагины:** `vim.pack`
- **LSP:** `vim.lsp`
- **Не используются:** `lazy.nvim`, `nvim-lspconfig`, Mason

## Требования

- Neovim `0.12.x`.
- Git для загрузки плагинов через `vim.pack`.
- `fzf` для работы нечёткого поиска.
- `ripgrep` для поиска по содержимому файлов.
- Nerd Font для корректного отображения иконок файлов.
- Инструменты, необходимые для сборки и установки парсеров Tree-sitter.
- Языковые серверы, установленные отдельно и доступные в `PATH`:
  - `gopls`;
  - `rust-analyzer`;
  - `lua-language-server`;
- Clippy для проверки Rust-кода (устанавливается командой `rustup component add clippy`);
- `rustfmt` для форматирования Rust-кода (устанавливается командой `rustup component add rustfmt`).

Плагины подключаются через `vim.pack.add()` при запуске Neovim. Их зафиксированные версии хранятся в `nvim-pack-lock.json`.

## Структура проекта

```text
~/.config/nvim/
├── init.lua                    # Точка входа: подключает основные модули
├── nvim-pack-lock.json         # Lock-файл vim.pack
├── README.md                   # Описание конфигурации
├── colors/
│   └── adwaita.lua             # Локальная цветовая схема
├── after/
│   └── ftplugin/               # Настройки отступов по типам файлов
│       ├── go.lua
│       ├── markdown.lua
│       ├── python.lua
│       ├── rust.lua
│       ├── xml.lua
│       └── yaml.lua
└── lua/
    ├── main.lua                # Базовые опции и leader-клавиша
    ├── plugins/
    │   ├── init.lua            # Порядок загрузки плагинов
    │   ├── autopairs.lua       # Парные скобки и кавычки
    │   ├── autotag.lua         # Автоматическое закрытие тегов
    │   ├── blink-cmp.lua       # Автодополнение и сниппеты
    │   ├── bufferline.lua      # Вкладки открытых буферов
    │   ├── fzf-lua.lua         # Нечёткий поиск файлов, текста и буферов
    │   ├── gitsigns.lua        # Подсветка изменений Git
    │   ├── lualine.lua         # Строка состояния
    │   ├── nvim-tree.lua       # Файловый менеджер
    │   ├── nvim-treesitter.lua # Парсеры и подсветка Tree-sitter
    │   ├── nvim-web-devicons.lua
    │   └── which-key.lua         # Подсказки по сочетаниям клавиш
    └── lsp/
        ├── init.lua            # Общие настройки LSP и диагностика
        ├── gopls.lua           # Go
        ├── lua_ls.lua          # Lua
        └── rust_analyzer.lua   # Rust
```

`init.lua` последовательно загружает `main`, `plugins` и `lsp`. Внутри `lua/plugins/init.lua` порядок подключения важен: например, иконки загружаются до зависимых от них плагинов.

## Базовые настройки

- Включены номера строк и 24-битные цвета.
- Используется локальная тёмная цветовая схема `colors/adwaita.lua` на палитре GNOME Adwaita.
- Буфер обмена Neovim объединён с системным (`unnamedplus`).
- `<leader>` — пробел.
- По умолчанию используются отступы шириной 2 пробела, табы заменяются пробелами.
- Отображаются непечатаемые символы:
  - табы — `→ `;
  - пробелы и trailing whitespace — `·`;
  - неразрывные пробелы — `␣`.

### Настройки по типам файлов

| Тип файла | Отступ | Символ отступа |
| --- | --- | --- |
| Go | 4 | Таб |
| Python, Rust, XML | 4 | Пробелы |
| Markdown, YAML | 2 | Пробелы |
| Остальные | 2 | Пробелы |

### Tree-sitter

Автоматически устанавливаются парсеры:

- `go`;
- `gomod`;
- `gowork`;
- `rust`;
- `toml`;
- `lua`;
- `html`;
- `xml`;
- `markdown`;

Подсветка Tree-sitter включается для буферов, для которых доступен подходящий парсер.

## Форматирование

Go- и Rust-файлы автоматически форматируются перед сохранением средствами LSP: `gopls` использует `gofmt`, а `rust-analyzer` — `rustfmt`. Ожидание форматирования ограничено двумя секундами.

## Горячие клавиши

После нажатия префикса, например `<leader>` или `g`, `which-key.nvim` через 300 мс показывает доступные продолжения сочетаний и их описания.

### Общие

| Клавиши | Режим | Действие |
| --- | --- | --- |
| `<leader>e` | Normal | Открыть или закрыть файловый менеджер |
| `<S-h>` | Normal | Перейти к предыдущему буферу |
| `<S-l>` | Normal | Перейти к следующему буферу |
| `<leader>bd` | Normal | Закрыть текущий буфер |
| `<leader>bo` | Normal | Закрыть остальные буферы |

### Нечёткий поиск

| Клавиши | Режим | Действие |
| --- | --- | --- |
| `<leader>ff` | Normal | Найти файл |
| `<leader>fg` | Normal | Найти текст в файлах |
| `<leader>fb` | Normal | Выбрать буфер |
| `<leader>fh` | Normal | Найти страницу справки |

### Файловый менеджер

Клавиши работают внутри окна NvimTree. Стандартные привязки плагина также сохраняются.

| Клавиши | Действие |
| --- | --- |
| `l`, `<Right>` | Раскрыть каталог либо перейти к первому элементу уже раскрытого каталога |
| `h`, `<Left>` | Закрыть каталог или перейти к родительскому каталогу |
| `l` | Открыть файл |

Файловый менеджер имеет ширину 50 колонок, группирует пустые каталоги и закрывается после открытия файла. Встроенный `netrw` отключён.

### Автодополнение

| Клавиши | Действие |
| --- | --- |
| `<C-n>`, `<C-p>` | Выбрать следующий или предыдущий вариант |
| `<C-y>` | Подтвердить выбор |
| `<C-e>` | Закрыть меню |
| `<C-Space>` | Открыть меню или документацию |
| `<Tab>`, `<S-Tab>` | Перейти к следующему или предыдущему месту вставки в сниппете |

Документация для вариантов дополнения появляется автоматически. Варианты не выбираются и не вставляются автоматически без подтверждения.

### LSP

| Клавиши | Режим | Действие |
| --- | --- | --- |
| `gd` | Normal | Перейти к определению, если сервер поддерживает эту возможность |
| `K` | Normal | Показать документацию для символа под курсором |
| `grn` | Normal | Переименовать символ |
| `gra` | Normal, Visual | Показать доступные действия с кодом |
| `grr` | Normal | Показать ссылки на символ |
| `gri` | Normal | Перейти к реализации |
| `gO` | Normal | Показать список символов текущего документа |
| `<C-s>` | Insert | Показать сигнатуру функции |

`gd` настраивается в `lua/lsp/init.lua`; остальные перечисленные клавиши являются стандартными привязками Neovim LSP. Диагностика отображается встроенным текстом (`virtual_text`).

## Языковые серверы

Конфигурации используют встроенный `vim.lsp.config()` и `vim.lsp.enable()`. Общие capabilities для автодополнения предоставляет `blink.cmp`.

| Сервер | Типы файлов | Маркеры корня проекта |
| --- | --- | --- |
| `gopls` | `go`, `gomod`, `gowork`, `gotmpl` | `go.work`, `go.mod`, `.git` |
| `rust_analyzer` | `rust` | `Cargo.toml`, `rust-project.json`, `.git` |
| `lua_ls` | `lua` | `.luarc.json`, `.luarc.jsonc`, `.luacheckrc`, `.stylua.toml`, `stylua.toml`, `selene.toml`, `selene.yml`, `.git` |

Для `lua_ls` отключены телеметрия и проверка сторонних библиотек, а `vim` объявлен глобальной переменной.

Для Go в `gopls` включены дополнительные проверки Staticcheck. Для Rust `rust-analyzer` при сохранении файла запускает `cargo clippy` вместо обычной проверки. Результаты проверок отображаются через стандартную диагностику Neovim.
